# Option B Setup — Claude Code (CLI/App/IDE)

This guide solves the role isolation problem in Option B, where every session sees the same knowledge files.

---

## The Problem with Default Option B

Claude Code uses a single `CLAUDE.md` and a shared filesystem — every session sees every role's knowledge files at once, causing Claude to "know too much" and skip steps.

## Solution — separate knowledge directory per role + slash commands

---

## Step 1 — Directory Structure in Your Project

```
my-project/
  CLAUDE.md                        ← Dev role instructions (generated by Lead)
  ai/                              ← copy the entire folder from sdlc-playbook/ai/ (setup.md does `cp -r` for all 6 files)
    PROJECT_INSTRUCTIONS.md
    SA_PROJECT_INSTRUCTIONS.md
    LEAD_PROJECT_INSTRUCTIONS.md
    QA_PROJECT_INSTRUCTIONS.md
    DEV_PROJECT_INSTRUCTIONS.md      → content referenced by CLAUDE.md that Lead generates above (Dev has no separate slash command)
    SEC_PROJECT_INSTRUCTIONS.md      → copied along with the folder but not used in Option B (no `/sec` — see docs/guides/SEC_GUIDE.md)
  .claude/
    commands/                      ← copy from sdlc-playbook/templates/option-b/commands/
      po.md                        → /po slash command
      sa.md                        → /sa slash command
      lead.md                      → /lead slash command
      qa.md                        → /qa slash command
  docs/
    roles/
      po/                          ← PO knowledge files only
        PROJECT_CONTEXT.md
        PATTERN_LIBRARY.md
        DECISION_LOG_[feature]_TODO.md
        DECISION_LOG_[feature]_RESOLVED.md
      sa/                          ← SA knowledge files only
        STACK_CONTEXT.md
        SOLUTION_PATTERNS.md
        Solution_Doc_[feature].md
        adr/
          INDEX.md
          ADR-001_[title].md
      lead/                        ← Lead knowledge files only
        LEAD_HANDOFF_[feature].md
      qa/                          ← QA knowledge files only
        [feature]/
          TestCases_[TaskID].md
          TestSuite_[feature].md
          BugReport_[TaskID].md
          TestReport_[feature].md
    shared/                        ← files visible to all roles
      tasks/
        Task_[ID]_[title].md
      TASK_LOG.md
```

---

## Step 2 — Run /setup to Create the Structure Automatically

Copy just one file first:

```bash
mkdir -p my-project/.claude/commands
cp sdlc-playbook/templates/option-b/commands/setup.md my-project/.claude/commands/setup.md
```

Then open Claude Code in `my-project/` and type:

```
/setup
```

Claude will:
1. Find the sdlc-playbook path automatically (or ask if not found)
2. Create the entire directory structure (`docs/roles/`, `docs/shared/`)
3. Copy the `ai/` folder and all slash command files
4. Create the initial `CLAUDE.md` (Dev role) and `TASK_LOG.md`

> **Manual setup (alternative):** To copy files manually, see the bash commands in [Manual Setup](#manual-setup) below

---

## Step 3 — Start a Session per Role

Open Claude Code in `my-project/` and type the slash command for the role you need:

| What you want to do | Type |
|---|---|
| Analyse a PRD, create handoffs | `/po` |
| Design a solution, create ADRs | `/sa` |
| Break down tasks, create task prompts | `/lead` |
| Implement a task (default) | No command needed — Claude reads CLAUDE.md automatically |
| Write/run test cases | `/qa` |

---

## Isolation Achieved

| Session | Reads from | Writes to |
|---|---|---|
| `/po` | `docs/roles/po/` | `docs/roles/po/` |
| `/sa` | `docs/roles/sa/` | `docs/roles/sa/` |
| `/lead` | `docs/roles/lead/` + `docs/shared/` | `docs/roles/lead/`, `docs/shared/tasks/` |
| Dev (CLAUDE.md) | `CLAUDE.md`, `docs/shared/` | code, `docs/shared/TASK_LOG.md` |
| `/qa` | `docs/roles/qa/` + `docs/shared/` | `docs/roles/qa/` |

Claude focuses on its own role's directory — it isn't blocked from other files, but has no reason to read them.

---

## STACK_CONTEXT.md — Special Case

This file must be present in multiple roles:

| Role | Path |
|---|---|
| SA (owner/creates) | `docs/roles/sa/STACK_CONTEXT.md` |
| PO (uses to verify stack) | `docs/roles/po/STACK_CONTEXT.md` |
| Lead (embedded in LEAD_HANDOFF) | embedded inside `docs/roles/lead/LEAD_HANDOFF_[feature].md` |
| Dev (embedded in CLAUDE.md) | Lead extracts and includes in `CLAUDE.md` |

After SA creates it, copy to `docs/roles/po/` as well.

## Manual Setup

If you prefer not to use `/setup`, copy manually:

```bash
# copy role instruction files
cp -r sdlc-playbook/ai/ my-project/ai/

# copy slash command templates (including setup.md)
mkdir -p my-project/.claude/commands
cp sdlc-playbook/templates/option-b/commands/*.md my-project/.claude/commands/

# create knowledge directories
mkdir -p my-project/docs/roles/po
mkdir -p my-project/docs/roles/sa/adr
mkdir -p my-project/docs/roles/lead
mkdir -p my-project/docs/roles/qa
mkdir -p my-project/docs/shared/tasks
```

## Version Header

Every knowledge file must have this header on the first line:

```
# Last updated: YYYY-MM-DD | Version: N
```
